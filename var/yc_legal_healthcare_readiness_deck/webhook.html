Integration boundary / server-side policy primitive

Webhook controls start disabled and precise.

The product does not expose an arbitrary callback mechanism. Future provider integrations must pass a narrow destination, payload, signature, and replay-control policy before delivery exists.

01 / DEFAULT

Delivery is off.

Webhook delivery requires an explicit enablement variable and a non-empty allowlist.

DEFAULT: DISABLED
02 / DESTINATION

Allow exact HTTPS hosts only.

The destination host must match a configured allowlist exactly. No wildcard or arbitrary callback.

ALLOWLIST: EXACT HOST
03 / REJECT

Refuse unsafe URLs.

Non-HTTPS URLs, credentials, ports, loopback, local, and private-network hosts are denied.

SSRF SURFACE: REDUCED
04 / MINIMIZE

Emit only safe events.

Only ID, type, timestamp, and optional correlation ID are valid in the provider-neutral event shape.

NO REPORT OR RECIPIENT DATA
05 / VERIFY

Validate inbound requests.

Future inbound integrations need a 32+ character HMAC secret, timestamp skew limit, and constant-time signature check.

REPLAY WINDOW: BOUNDED
MODE B OVERRIDE
When Healthcare Mode B is enabled, webhook delivery remains disabled regardless of configuration. No healthcare provider webhook or connector is enabled by this release.
