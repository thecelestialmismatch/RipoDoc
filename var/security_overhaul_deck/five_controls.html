03 / Identity hardening
AUTHENTICATION CONTROL MAP

Five attack paths received specific controls.

The release does not rely on one generic “secure login” claim. Each common abuse path has a distinct server-side control.

01

User enumeration

One generic response, a dummy scrypt check for unknown users, and a fixed response-time floor.

02

Automation & abuse

Privacy-hashed IP and email rate limits, with Cloudflare Turnstile verified on production auth actions.

03

Unverified activation

A new account remains inactive until an emailed one-time verification code is consumed.

04

Password compromise

Passwords use scrypt with a random salt, a 64-byte derived key, and constant-time comparison.

05

Reset takeover

Random 32-byte codes are HMAC-stored, single-use, 30-minute limited, and never placed in URLs.

Design principle: unknown, invalid, and expired paths are intentionally made hard to distinguish from their valid counterparts.
