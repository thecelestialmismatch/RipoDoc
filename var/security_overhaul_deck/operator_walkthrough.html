SELF-HOSTED DEPLOYMENT RUNBOOK

Six disciplined steps
from clone to control.

The self-hosted bundle is designed for an MSP-operated environment—not an exposed document-processing endpoint.

01

Prepare the managed host

Clone the reviewed repository on an MSP-controlled Docker host; restrict the operator directory.

02

Create a locked-down environment

Use a root-owned .env with distinct database, auth, and evidence secrets plus the canonical HTTPS origin.

03

Build and start Compose

Confirm a healthy PostgreSQL service and a loopback-only 127.0.0.1:4000 worker mapping.

04

Terminate TLS at the edge

Publish only the web service through the MSP reverse proxy. Do not expose the worker port publicly.

05

Verify the account lifecycle

Test email verification, sign-in, tenant authorization, and reviewed worker publication with a controlled inbox.

06

Back up, validate, update

Back up PostgreSQL first, pull reviewed changes, rebuild, and rerun the release gate before rollout.

Operational rule: the production app origin, reverse proxy host, and Turnstile domain must agree exactly. The worker’s CORS allowlist is a browser boundary, not a replacement for keeping the worker private.
