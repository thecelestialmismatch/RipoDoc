# RipoDoc Project Context for Hermes Agent

## Project Overview
RipoDoc is a secure reporting delivery and evidence layer for Managed Service Providers (MSPs). It transforms static PDFs, CSVs, and BI exports into interactive, auditable, client-facing reports.

## Tech Stack (Strict)
- **Backend:** Go 1.24+ (chi router, pgx, sqlc, River queue)
- **Frontend:** Next.js 16.2, React 19.2, TypeScript 5.9, Tailwind CSS 4.1
- **Database:** PostgreSQL 18.4 (Row-Level Security mandatory)
- **Infra:** AWS ECS Fargate, S3, KMS, Textract, Redis 7.x

## Coding Conventions & Rules
1. **Security First:** All database queries MUST be tenant-scoped. Use PostgreSQL RLS. Never expose raw data without authorization checks.
2. **No Magic AI:** AI agents are author assistants only. They suggest; they never auto-approve, publish, or perform arithmetic. All calculations are deterministic (Go/SQL).
3. **Type Safety:** Use `sqlc` for all database interactions. No raw string concatenation for SQL.
4. **Error Handling:** Use `zerolog` for structured logging. Never swallow errors.
5. **Boil the Ocean Standard:** Documentation in `/docs` is the single source of truth. No scattered notes.

## Directory Structure
- `cmd/api/` - HTTP API server
- `cmd/worker/` - Background job processor (River)
- `internal/` - Business logic, handlers, middleware, models, workers
- `pkg/` - Reusable utilities (config, pdf, ocr, security)
- `web/frontend/` - Next.js application
- `docs/` - All product, engineering, and security documentation
