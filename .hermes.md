# RipoDoc Project Context

## Project overview

RipoDoc is a secure reporting-delivery and evidence layer for Managed Service Providers (MSPs). It preserves a normal PDF while allowing an authorized recipient to inspect approved source evidence through an expiring, revocable, recipient-bound, audit-logged experience.

## Current technology boundary

- **Application:** Next.js 16 App Router, React 19, TypeScript, Tailwind CSS.
- **Identity and workspace:** Custom server-side scrypt password hashing, opaque PostgreSQL sessions, email verification, HMAC CSRF, rate limits, and optional production CAPTCHA.
- **Persistence:** PostgreSQL via parameterized `pg` queries and transactions. Workspace/report paths are tenant-scoped.
- **Private processing:** Node.js worker in `docker/local/server.mjs`, reached only through a short-lived, tenant-bound, single-use server capability. Browsers never receive a worker URL or credential.
- **Evidence tooling:** TypeScript PDF generator and byte-preserving overlay tools in `tools/evidence-pdf`.
- **Deployment:** Public Next.js site on Vercel; customer-controlled self-hosting through hardened Compose. The public site is not the document-processing plane.

## Engineering rules

1. **Security first:** Scope every data read/write to the verified session tenant. Do not trust client-supplied tenant, role, report, draft, or worker identifiers.
2. **Private-worker boundary:** Do not expose worker endpoints, secrets, capabilities, report content, or untrusted PDF processing to the browser/public Vercel environment.
3. **Evidence integrity:** Preserve recipient binding, expiry, revocation, scope checks, and hash-chained audit behavior. Do not embed evidence rows in PDFs.
4. **No unsupported claims:** Do not claim hosted readiness, HIPAA compliance, BAA availability, billing, refunds, SLA, or legal terms without verified implementation and owner/counsel approval.
5. **Healthcare Mode B:** Treat Mode B as restricted evaluation/self-hosted posture. Do not allow PHI/ePHI through public intake, public authoring, ordinary email, public analytics, or webhooks.
6. **Type safety and tests:** Keep strict TypeScript, parameterized SQL, safe errors, and focused regression coverage. Run the full release gate before merge.
7. **Documentation discipline:** Keep the current architecture, security controls, launch facts, and legal-review status in `/docs`; do not preserve superseded implementation plans as active guidance.

## Directory structure

- `web/frontend/` — Next.js application, public routes, protected workspace, evidence routes, and server-side gateway.
- `docker/local/` — private self-hosted authoring worker.
- `tools/evidence-pdf/` — PDF writer, overlay engine, fixtures, and tests.
- `migrations/` — PostgreSQL schema evolution.
- `docs/` — product, research, engineering, security, legal-review, and operations documentation.
- `var/` — internal presentation/collateral projects; review claims before external use.
